## 做了什么

一、中转站（luruseng-relay 加 `/dgj`）：代码和测试做完，**没推上线**

- 新的 Durable Object 类 `Box`（迁移 v3），跟录入僧的 `Room`、点钞机的 `Quota` 分开。`src/dgj.js`，`src/index.js` 加一条路由，`wrangler.jsonc` 加绑定和迁移，README 加一节。
- 信箱号 128 位随机（32 个小写十六进制字）；站里只存密文，不拆、不看，日志不记内容。
- 两个方向：`to=pc`（手机 → 大管家）、`to=phone`（大管家 → 手机）。收信的一方连着 WebSocket 就马上推（48KB 以下的小信内容跟着推送走，省一次来回）；没连着就攒着，下次连上 `hello` 里一次给全。
- 收的一方处理完回 ack 才删；没人取的 7 天删（alarm），两头都收到 `gone`。
- 大管家在不在线：站里判断，掌机的 WebSocket 连着、90 秒内 ping 过算在线（拿 WebSocket 自动回 pong 的时间戳判，ping 不叫醒 Durable Object，半死的连接也不会一直显示在线）。
- 大的信在站里拆成 1.9MB 一片存（Durable Object 一行最多 2MB），取的时候拼回整封。一封最大 24MB，一个信箱没取的最多 200 封、64MB，超了回 413 / 429。
- 不带 Origin 的只有 `/dgj` 放行；录入僧 `/r`、点钞机 `/count` 照旧只认网页。跟站同源的 Origin 也放（Python 的 websocket-client 默认会带）。
- 免费额度：掌机长连着靠 WebSocket 休眠，文本 `ping` 由站里自动回 `pong`，不叫醒、不算时长。
- 推不上去：这趟是定时任务开的会话，git 代理不给 luruseng-relay 推送权限（「a run cannot add repositories」），GitHub 连接器也不让读写这个仓库；这台云机器连线上信箱的地址也被出口代理挡（403）。改动打成补丁放在 `ios/tools/relay/luruseng-relay-dgj.patch`（做在 luruseng-relay 8bb14c9 上，`git apply --check` 过），怎么推写在 `ios/tools/relay/README.md`。

二、接口 v2（`ios/docs/大管家接口.md`）

- 新加「v2：走 Cloudflare 信箱」一大节：为什么换、配对、信箱地址、一封信（加密前）、加密、收发、谁删什么、在线状态、出错怎么回、iCloud 备胎、免费额度。v1 原样留在后面当备胎。
- 信封 `v=2`，里面的 `data` 就是 v1 的请求 / 结果 / 送来，一字不改（`v` 还是 1）；原图、录音放 `files` 跟着信走。
- 加密：AES-256-GCM，nonce 12 字节随机，附加数据 `yiye-dgj/2/<信箱号>/<收信的一方>`，寄出去的是 nonce ‖ 密文 ‖ tag。给了一段「对一下」的样例：Node 的 WebCrypto 生成，Python 的 `cryptography` 拆开验过，YiyeKit 的单元测试也拆。

## 拍了什么板

- 客户端一封信一次 PUT、一次 GET，拆片在站里做：两头（Swift、Python）都不用管分片，最不容易写错。
- 收的一方办完才 ack，不是取走就删：掌机理到一半关了机，下次连上还在。
- 信封里 `data` 用 v1 原样：掌机现有的理顺代码能原样复用；手机走 iCloud 备胎时照旧写 v1 文件，掌机没升级之前（066 做完以前）也照样能用。
- 手机保活每 30 秒发 `{"t":"state"}`（顺便对一下大管家在不在）；掌机发文本 `ping`（不算额度）。
- 配对只认 `at` 更新的：扫码配的不会被 iCloud 里旧的配对文件换回去。
- `.github/workflows/ios-relay.yml` 是新加的：在 `ios/` 外面，但它只给一叶笺 iPhone 版用（跟 `ios.yml` 一样），用来跑 Swift 的手机这头对着真信箱来回 10 次。
