## 做了什么
1. **手机：存进一叶笺**（`SaveToYiyeIntent`，`openAppWhenRun = false`）：收网址和文字。有网址（参数里的、文字整段就是网址、或者短文字里夹着一个网址）→ 新建 `kind = "article"` 的便签（「全部」，不进文件夹），第一行网页标题（手机先自己拿 `<title>`，6 秒拿不到放网址），最后一行网址，寄 `ask=article`，回给捷径一句「存好了，大管家在扒正文。」。没配对、寄不出去：「存好了。大管家还没接上，正文先不扒。」。纯文字：直接存成普通便签，不寄。
2. **手机：两个按钮**（`ArticleBar`，文章便签写字页底部）：正文还在扒（或 10 分钟没回信）时灰着、写「大管家在扒正文」；扒失败：栏上写原因，按钮照样能用。「直接配音」= 现成的 `requestDub`（没进小耳机就放进去）。「简写」= 寄 `ask=simplify`，栏上「大管家在简写」；听力稿从「送来」一到，栏上变「简写好了，点这里去听」，点了进小耳机那一篇；原来那条便签不动。
3. **信**：写在 `ios/docs/大管家接口.md` 新开一节 v3.6（单子写的 v3.4 早被深聊用了）：`ask=article`（`url` → 回 `title` + `text`）、`ask=simplify`（便签全文 → 一到三条听力从「送来」回，每条带 `request`，全送完回一封 `ok` 的 `result`，`text` = 篇数）。字段、加密、收发照 v3，一个没改。
4. **大管家：扒正文**：Python 下载（只 http / https、不去内网地址、跳转后也查、3 MB 封顶、20 秒）→ trafilatura 抠标题和正文 → 脑子理一遍（删导航、广告、评论、「相关阅读」，理段落，一个字不改写）。脑子概括了（回得不到原文一半长）、出错或者超时，就用抠出来的原文，不会因为脑子丢文章。扒不到的一句人话：要登录 / 被带去登录页 / 挡机器人 / 没正文 / 404 / 太大 / 不是网页 / 连不上，都不硬试。中文文章照样扒。
5. **大管家：简写**：写法和词表读 tingli 分支的 `写法.md`、`词表.md`；不长写 1 篇，长的拆 2 到 3 篇（最多 3 篇，标题末尾带（1/3）），中文文章也简写成英文；每篇走现有的 `tingli.voice_one` 配音（Gemini 三个声音轮着，106 那套），配不了就送只有字的（小耳机里挂「重配」，112 的）；送法跟每天的听力稿一样（信箱，不行 iCloud）。`tingli.deliver / voice_one / words_only` 多了一个可选的 `request`。

## 我替你定了这些
1. **接口号 v3.6**（单子写 v3.4，已被深聊用）。
2. **「直接配音」用 `toggleListen`**：没进小耳机就放进去（顺手配音，大管家不在手机自己念），进了就重配。
3. **简写完不改原便签**；多篇只把栏上的「点这里去听」指向第一篇。
4. **存网页和存文字拆成两个捷径**：存网页的捷径 URL 格子放 Shortcut Input，分享类型只留 URLs / Safari web pages；存文字的另搭一个，Text 格子放 Shortcut Input（`捷径.md` 最后一节）。原因：一个捷径两个格子都放 Shortcut Input，文字塞进 URL 格子时快捷指令会报转换错误。这一条是我推的，没在真捷径里验过。
5. **不去内网地址**（127.x、192.168.x 等）：信是你手机寄来的，但大管家不该因为一封信就去开你家路由器的页面。
6. **脑子概括了就不用**：理正文的脑子回得不到原文一半长，就当它概括了，用抠出来的原文。
7. **手机先拿网页标题**（6 秒，只下前 200 KB），拿不到第一行放网址，等大管家扒回来再换成正式标题。

## 你要看的（真机，装 0.7.10）
1. **搭捷径**：照 `ios/docs/捷径.md`，Safari 里分享一个网页，顶上应该弹「存好了，大管家在扒正文。」。
2. **便签变干净**：几秒到几十秒后，一叶笺里那条文章便签的正文换成大管家扒好的（第一行标题，最后一行网址）。
3. **两个按钮**：「直接配音」→ 进小耳机、配音；「简写」→ 栏上「大管家在简写」，几分钟后小耳机当天那组出现一到三篇、栏上变「简写好了，点这里去听」。
4. **扒不到的**：分享一个要登录的页面（比如 GitHub 设置页），栏上应该写「这页要先登录…」，两个按钮还能点。
